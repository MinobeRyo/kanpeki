# カンペき：画面サイズを考慮した配置案

設計検討のみ。ImageGenの画像は見た目の参考で、実装済み画面や寸法の厳密な検証ではない。下記数値は設計上の目標。ユーザーの機種は未確認。

## iPhone：393×852pt（仮基準）

上下の安全領域を仮に59pt／34ptとし、実装時には端末が返す値に追従する。背景のみ全面に広げ、操作部分を安全領域内に収める。

| 領域 | 配置・寸法の目標 |
|---|---|
| ヘッダー | 上の安全領域の下。ブランドとメニュー。操作対象44pt以上 |
| 残り時間 | 上部、56ptの数字。ゼロで振動、ページは送らない |
| 原稿 | 中央、左右16pt余白。26ptを基準に短いまとまりで表示 |
| 分析 | 原稿の下に小さな状態表示のみ。詳細は別画面 |
| スライド | x=16、y≈603、幅361、高さ≈203pt（16:9の場合） |
| ページ番号 | スライドの直上 |
| 下端 | スライドから安全領域まで12pt空ける。下にボタンを置かない |

スライドの右半分を短くタップすると進み、左半分で戻る。指を動かすと即ポインターへ移行し、指を離してもページを送らない。長押しや次へボタンは不要。判定閾値は実機確認で決定する。

狭い画面では時間・原稿領域を先に詰め、下部スライドと安全領域を優先する。文字を極端に小さくして収めない。文字拡大時は原稿をスクロール可能にし、スライド操作と分離する。4:3資料は縦横比を維持して表示枠に収め、余白へのタップは送信しない。横向きと固定カメラモードの実寸画像は今回の3枚には含まない。

## 接続画面

「Macにつなぐ」→QR読取→接続先の確認→資料待ち／準備画面。カメラ未許可の場合は用途説明と許可の選択を先に出す。拒否時もコード入力を使える。
キャラクターは下部で次の操作を一言案内する。「スキップ」は案内を閉じる意味で、接続を完了した扱いにはしない。画像の表記は次の調整で「案内を閉じる」に揃える。
同じWi-Fiは想定条件であり、学内ネットワークの端末間通信制限などによる接続失敗は別途案内する。QRは見本で実接続用ではない。

## Mac：1440×900の表示領域（仮基準）

外側余白32、列間24。左944幅をスライドと原稿、右408幅を準備パネルに割り当てる。16:9のスライドは944×531を目標とする。ウインドウ上部52、下部は開始操作と任意の案内用。本文18を目安とし、右側の翻訳と原稿チェックは必要時のみ開く。
ウインドウが狭い場合は補助パネルを閉じて呼び出す方式へ切り替え、スライドを歪めない。長い翻訳や原稿はパネル内でスクロールする。生成画像内の厳密な寸法はこの目標値からずれている。

## 他画面に適用する原則

準備・固定カメラ設定・分析結果も同じ余白と文字寸法を使う。一画面に全分析を並べず、結果の概要から「話し方」「カメラ」を開く。カメラ結果は観測可能な動きと測定不能を区別し、理解度・感情を断定しない。入力やモデルが使えなくても発表の基本操作を止めない。
カラオケ風の原稿強調は視覚案であり、発話との自動同期は未確定。スライドの自動送りには結び付けない。

## 色と画像

淡い緑＝背景、アイボリー＝内容面、スレート＝文字・操作、コーラル＝キャラクターと重要な注意。生成画像の緑の状態点は実装時にスレートのアイコン＋状態文へ統一する。状態を色だけで伝えない。
サンプル原稿・時間・グラフは仮データ。確認は画像の目視のみで、実機の可読性・片手操作・通信・音声処理は未検証。
