# 映像解析の実装範囲

2026-09-15のローカル映像読み取り技術の反映と現状UIへの適合の指示に基づく。Issue #14のうち、Mac/iPhone入力、顔の向き・うなずき候補、較正、カメラ準備・状態・結果を実装する。

## 構成

AVFoundationで映像を取得し、Apple Visionで顔とランドマークを抽出する。画面左上原点の顔枠と、下向きが負のpitchへ統一する。顔枠・角度・目と鼻の位置はJavaScriptCore上の共通時系列エンジンに渡す。Mac/iPhoneとも撮影端末内で処理し、生映像・顔画像・個人識別情報を永続保存・送信しない。

複数領域で小さい顔を追加探索し、重複した枠を除去する。顔の対応付けは一対一で行い、急な顔サイズ変化や入力断で履歴を引き継がない。対象は観客／発表者を人間が指定し、人数による自動切替は使わない。

頷き候補は目間距離で正規化した鼻の縦位置から提案し、19特徴の判別器で約0.6秒後に確定する。候補をキューで扱い、追跡開始直後の1秒は基準を準備する。ランドマークがない入力は角度による補助経路を使う。iPhoneの動きを検出した区間は候補を抑制する。

推論は専用直列キューで実行し、遅れた映像は捨てる。解析目標は25fps、熱状態serious/criticalなら6fpsへ下げる。初期実装値であり、全端末の速度・電池持ちを保証しない。UI更新は最大4回/秒。入力が1.1秒以上途絶えたら未計測とし、iPhoneの背景移行・カメラ中断時は停止する。再開は人間の操作で新しい計測として行う。MacはPowerPointへのアプリ切替でも計測を続ける。

## 既存UIへの対応

| 画面 | 接続した内容 |
|---|---|
| Mac準備／発表画面 | 左の補助領域にカメラ分析の入口と短い状態表示。共有スライド・原稿・操作は維持 |
| iPhone画面 | 既存の「…」内からカメラの設定・結果を開く。稼働状態だけを原稿の下に表示 |
| B03 撮影範囲の確認 | 「入力を確認」で対象・前後カメラ・利用目的を確認し開始。分析なしで元画面へ戻れる |
| B05 詳細 | プレビュー、顔数、入力品質、発表者向き先の任意較正。既定では詳細指標を折りたたむ |
| R03／R05 結果 | 観察できた時間・未計測時間・観客のうなずき候補のあった時間。観客と発表者を混ぜない |

パネルを閉じても計測を継続し、結果のためにスライド操作を繰り返し中断しない。左右タップ・下部配置などUI全体の変更は既存の担当作業と統合する。カメラの結果がページ送りやタイマーを操作することはない。

## 表示値の意味

頷き候補は1秒ごとの有無を集計し「候補のあった時間」として表示する。動作回数や人数ではない。較正による向き先は頭部姿勢の近似であり、視線や理解度ではない。顔向きを取得できない秒、入力断、端末移動を未計測・判別不能とし、観客の反応ゼロと混同しない。秒数は時刻窓による概算。

結果はメモリ内のみで、新しい分析の開始かアプリ終了で破棄する。時系列グラフ、セッション保存、端末間結果同期、笑顔・感情・関心度・理解率は今回の実装に含まない。両端末で独立にカメラを開始できるが、結果を合算しない。

## 技術選択の根拠と限界

ローカル検証では低解像度の小さい顔の角度揺れが微小な頷きを上回り、角度閾値の調整には限界があった。ランドマークと候補判別器は区間外検出を削減したが、見落としは残る。顔検出の成功、合成入力の回帰テスト成功、一般精度は別の指標として扱う。

判別器はAMI由来の暫定重み。評価済みデータを次の未見評価に再利用しない。学習・評価映像や過去の成果物を同梱しない。拡大クロップ、顔領域全体の動き、口の動きを使う追加判別器は標準経路に採用しない。Apple向けの統合であり、MediaPipeなど別推論器での同等性能は主張しない。

## 必要な確認

回帰テストでは入力断、移動抑制、短い頷き、顔の入れ替わり、較正の欠落と境界、時刻の逆転、永続化対象を確認する。実機では前後カメラ、権限拒否・取消・背景復帰、連続計測、温度、画面共有との同時負荷を確認する。Issue #14の実会場・距離・照明・遮蔽・電力の検証と笑顔判定は未完了。
