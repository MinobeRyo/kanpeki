# 技術構成の引き継ぎ（実装前）

採用済みは製品の役割分担と操作方針。以下の境界・入出力は実装を合わせるための提案で、通信ライブラリ・モデル・OS最低版は未確定。

## 役割

Macをセッション、現在ページ、基準時間の管理元とする。既存プレゼンアプリがスライドを描画し、カンペきが対象画面と操作を扱う。PPTXのノートをスライドごとに読み取り、画像だけへ変換して失わない。PowerPointを最初の対象とし、Keynote／Canvaの表示・ノート取得・操作は対応可否を分けて後から拡張する。

iPhoneはMacの現在状態を表示し、手動の送り戻し・ポインター・振動を担当。固定モードではカメラ入力として使い、手持ちと同時にできると見なさない。Macや別端末による入力は選択式にする。

準備補助はMacのローカルLLMで翻訳と原稿分析。モデル取得・空き容量・メモリ・対応ハードウェア・ライセンス・待ち時間を確認する。OSに必要なモデルが既にあるとは仮定しない。分析不能でもスライド操作を可能にする。

## 接続境界の提案

| 境界 | 合わせる項目 | 失敗時 |
|---|---|---|
| 資料→セッション | 資料ID、ページID、順序、ノート、表示元 | 読込不能・ノートなし・表示アプリなしを区別 |
| iPhone→Mac | セッションID、操作ID、操作種別、対象ページ、ポインター座標 | 重複・古いセッションを無効化 |
| Mac→iPhone | 現在ページ、状態の版、基準時間、表示画像 | 切断表示。再接続時は最新状態へ同期 |
| 音声／カメラ→分析 | 入力元、共通時間軸、観測値、測定可否 | 欠測を0にしない |
| 分析→結果 | イベント時刻、ページ対応、候補・根拠、未計測 | 原音未保存なら再生ボタンを出さない |

ポインターは実際のスライド領域内の正規化座標で扱う案。余白や縦横比の違いを座標へ混ぜない。移動中の通信は最新位置を優先できるが、ページ送りは順序と一回性が必要。再接続時に古いタップを再送しない。
音声と映像の重複集計を避け、まず主音声1入力・カメラ1入力を提案する。端末時計の差、途中再接続、スライド戻りを含めて検証する。

## 最初に実機で確かめること（開始指示後）

1. MacでPPTXを選択→対象プレゼン表示を取得→ノートとの対応。全画面にしてから資料を選ばせない。
2. 会場ネットワークでペアリング→両画面の同じページを表示。
3. 左右タップ30回、ドラッグ後の指離し、切断・再接続で重複や意図しない送りがないこと。
4. 時間切れの振動、固定時の通知、バックグラウンド・ロック時の挙動。
5. 短い音声のフィラー／無音候補、カメラの観測値と欠測、Mac上の解析所要時間。
6. 新アプリの同一コミットからビルド・配布し、4人が版を確認。

これは検証計画。達成値を記録して初めて検証済みにする。配布方法の制約（画面取得、既存アプリ操作、サンドボックス、必要権限）は採用方式で確認する。
