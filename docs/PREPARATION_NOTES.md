# 発表前に原稿の要点案を準備する

Issue #86。完成原稿の生成や翻訳ではなく、準備アプリで原文から選んだ要点を、本体で確認して手元の原稿として使う機能です。機器の接続準備と、話す内容の準備は別々に進められます。iPhoneが未接続でもMacで確認・採用できます。分析を使わず、元のPPTXノートで発表することもできます。

## 用意するものと順序

1. 保存済みPPTXをMac本体で読み込みます。元ノートは保持され、PPTXへの書込みはしません。
2. 本体のChatGPT欄で共有フォルダーを選択します。[MCPの起動・接続](MCP_INTEGRATION.md)が別途必要です。資料本文・ノートを共有する操作であり、完全オフラインの分析ではありません。
3. `SlidePacer`準備アプリで**同じ共有フォルダー**を選び、「Mac本体の資料を読み込む」を押します。PPTXを二つのアプリで別々に解釈せず、本体が解決したページ順とノートを使います。
4. 既存の目的・聴衆・持ち時間を入力し、ChatGPTへの分析依頼を準備します。依頼文をChatGPTへ送り、原文照合と時間配分が完了するまで待ちます。取消・入力変更・再分析の場合は、以前の案を新しい結果と扱いません。
5. Mac本体の「原稿案を確認」で、各ページの**元の原稿と要点案**を確認します。「閉じる」は取消、「要点案を採用」で初めて本体へ適用します。要点案は完成原稿や翻訳ではありません。数値・条件・引用の意味を自分で確認してください。
6. iPhoneを接続し、PowerPointの同じ資料の共有・ページ観測を有効にします。iPhoneの原稿に「採用した要点案（原文は保持）」が表示され、現在ページの案だけが届きます。接続・画像・資料が一致しない間は基本の同期保護を維持します。
7. 発表前に必要なら同じ確認画面から「元の原稿に戻す」を選びます。開始・一時停止中・終了処理中は採用や復元できません。次の発表へリセットしたら再確認します。

## 安全境界

- 完了した分析依頼ID、資料版UUID、全ページのslideID・順序・本文・ノートのSHA-256を照合します。確認後の接続イベント、共有先、タイマーsession/revision、資料・依頼・案の変更は採用を拒否します。
- 接続は確認の前でも後でも構いません。確認途中の接続変化だけは再確認が必要です。採用済みの同じ資料は、後から接続したiPhoneでも使えます。
- 準備中に分析を更新・取消すると案を無効化して元原稿へ戻します。本番中は採用済み内容を固定し、新しい分析や取消で突然差し替えません。新しい発表へのリセット・資料再取込で採用状態を破棄します。
- 共有ファイル`preparation-notes.json`は512KiB、1ページのUTF-8本文は16KiBまで。上限超過は拒否し、切り捨てません。原文・promptを含む`analysis-report.json`はiPhoneへ送りません。端末間は既存stateの現在ページ原稿と出所表示だけです。
- 専用ファイルはMCP共有フォルダー内に残ります。フォルダーは非公開・Git対象外に置き、共有済み資料の削除は利用者が管理します。Macで採用した状態はメモリのみで、永続の練習履歴を作りません。

## 検証

`bash scripts/check.sh core`に、資料変更・順序・ID・UTF-8上限・確認取消・接続/資料/タイマー/共有世代変更・本番適用拒否・原稿復元・ファイル往復の純粋チェックを追加。既存WireCodecでも現在ページ原稿/出所/slide identityの往復を確認します。`make slidepacer-test`、`make slidepacer-build`、Mac/iPhone署名なしビルドも実行対象です。

実ChatGPTの返却、実PowerPoint・会場LAN・iPhone画面での一巡、利用者による要点品質、今回差分のTestFlight配布は別途確認が必要です。合成回帰とビルドの成功を、その実機成功とは扱いません。
