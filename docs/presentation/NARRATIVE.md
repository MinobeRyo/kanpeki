# カンペき 発表原稿と共有方針

2026-09-15。ユーザー承認の発表軸をまとめた資料。PPTXは本編7枚＋補足1枚。

## 他のAIへの共通方針

価値は、振り返れなかった学生が最初の改善に踏み出すこと。発表前・本番・発表後をつなぎ、録画・記録の探索や資料との照合、既存AIに説明し直す手間を減らす。独自の分析AIに正解を学習させることを目的にしない。AIの提案から何を直すかは本人が選ぶ。

実装・CI・実機確認・配布を区別する。設計画面を実機画面と扱わず、効果や精度の数値を作らない。参考の改善例も実測結果と表示しない。

## 発表者ノート

### 1枚目

発表を録画してAIに相談すればいい。でも、そこまでできている学生はどれくらいいるでしょうか。私たちは、改善したいのに振り返りまで辿り着けない学生を支える、カンペきを作っています。
出典: 2026-09-15ユーザーの発表方針と提供ロゴ。学生全体の利用率を示す調査結果ではなく、チームが対象とする課題です。

### 2枚目

録画して、資料と照らし合わせ、気になる場面を探して、AIに説明する。改善のために使いたい時間を、その準備に取られてしまいます。乾さんが整理した課題は、準備する、話す、振り返る、直すという段階の間に、発表者自身がつなぐ手間が残っていることです。
出典: ユーザーが共有した乾映之右さんの課題文。効果量や利用率は未測定。

### 3枚目

カンペきはMacとiPhoneをつなぎ、発表の前・最中・後を一つの流れで支える設計です。前は資料と原稿を準備し、本番はスマホで資料を操作しながら時間を把握する。終了後は録音の気になる箇所を聞き直します。画面は事前に作った設計イメージです。全段階の完全自動連携を実証したという意味ではありません。
資料: specs/PRODUCT.md、specs/ASSISTANCE_FLOW.md。画像: assets/design/device-size/iphone-live.png。

### 4枚目

具体例は録音後のフィラー候補です。時刻と発話の前後を見て、その場面を聞き直す。無駄な発話と一律に決めつけるのではなく、本人が文脈を確かめて、次に何を変えるかを選びます。例えば冒頭の説明を一文短くする、といった改善です。この改善例は説明用で、実測結果ではありません。候補表示・前後音声再生の実装はPR69、iPhoneビルドとCI成功。会場の実iPhoneでの再生と検出精度評価は別途確認が必要です。
根拠: https://github.com/MinobeRyo/kanpeki/pull/69

### 5枚目

私たちが力を注ぐのは、既存のAIが役立つところまで利用者を無理なくつなぐことです。カンペきが資料や発話、時間をまとめ、既存AIが改善候補を提案し、最後に本人が選びます。独自分析AIに正解を学習させることをゴールにはしていません。ここは設計方針であり、全データの自動送信・AI助言の実資料精度・全体連携の検証完了を主張するスライドではありません。
関連: https://github.com/MinobeRyo/kanpeki/issues/33 、https://github.com/MinobeRyo/kanpeki/issues/82

### 6枚目

Codexはコードを書くだけでなく、何を削るかの壁打ちから使いました。たとえば画面の常時表示ボタンを三つまでに絞る方針をAGENTS.mdに残しています。分担はIssueとworktreeで管理し、PRのCIでMacとiPhoneを確認。その後はGitHub ActionsでTestFlightへ配布し、Slackで変更内容と確認方法を伝えます。AIの成果物を人間が試すまでの距離を縮めました。CI成功と実機で使えることは分けて確認しています。既存の構成・事前成果の持ち込みはdocs/MIGRATION.mdに記録しています。
根拠: PR70 https://github.com/MinobeRyo/kanpeki/pull/70 、PR71 https://github.com/MinobeRyo/kanpeki/pull/71 、PR78 https://github.com/MinobeRyo/kanpeki/pull/78

### 7枚目

私たちが目指すゼロから一は、振り返りをしなかった人が、最初の改善に踏み出すことです。発表前・本番・発表後をつなぐことで、記録を探したり相談の準備をしたりする時間を減らし、自分の伝え方を直す時間に変えていきます。カンペきです。

### 8枚目

2026-09-15作成時点。左側は実装とビルド・一部統合試験の確認範囲で、全員の実機動作保証ではありません。右側を完了済みとして説明しないでください。独自AIの精度優位性、学生全体の改善効果、全員へのインストール完了は確認していません。補足資料は本PPTXのノートと同梱Markdownにも収録しており、GitHubを閲覧できない審査員にはそれらを渡せます。Issueリンクは非公開リポジトリのためチーム限定です。
