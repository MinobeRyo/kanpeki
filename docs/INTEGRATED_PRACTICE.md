# 準備・練習・音声・AIを一つのアプリで使う

Issue #92。2026-09-15の統合branchの説明です。main・配布の現在値はIssue/PRで確認してください。

## 練習の一巡

1. Macホームの「練習する」を開く。初回は分析モデル（約142MB）を取得し、「音声の受信を開始」。
2. iPhoneをQRで接続する。承認済みの暗号化ペア通信で音声のURL・コードを自動共有するため、接続コードの別入力は不要。
3. Macで「練習を開始」。目標時間の初期値は5分で、設定から変更できる。資料やPowerPointの画面共有がなくても開始できる。
4. iPhoneのメイン画面で「録音を始める」。終了は「録音と練習を終了」。マイクと送信は利用者が明示操作する。切断・バックグラウンド移行でも録音を停止する。
5. iPhoneで「Macで分析する」。Mac内のWhisperで処理し、「話し方の結果・聞き直し」から文字起こし、推定話速、フィラー候補・低音量区間の再生へ進む。
6. Macの「AIの振り返りを開く」。初回は既存MCPの共有フォルダーを選ぶ。「音声：取得済み」を確認し、「AIへの依頼文をコピーしてChatGPTを開く」。ChatGPTでカンペきのMCPを選び依頼文を送る。具体的な修正と次の練習がMac/iPhoneへ戻る。
7. 「次の練習を準備」で次の発表IDに切り替える。iPhoneの前の録音は勝手に消さず、新しい録音を始めるときに破棄を確認する。

MCPサーバー・ChatGPTのカスタム接続は既存の[設定](MCP_INTEGRATION.md)を利用する。アプリだけでChatGPTへの送信が自動実行されるわけではない。AI待機と音声の未取得は画面で区別する。

## 資料と原稿の準備

「発表準備」でPPTXを選ぶ。「準備・機能」→「資料をAIで整理する」から、従来のSlidePacer画面をMac本体内で開く。同じ共有フォルダーを引き継ぎ、Macの資料を読み込む。目的・聴衆・時間を設定しMCPへ依頼する。結果の原文ID照合・時間配分は引き続きSwiftが行う。

分析後の「原稿案を確認・採用」で元原稿と要点案を比べる。同じ資料・ページを観測したときに採用原稿をiPhoneへ送る。資料選び直しや発表ID変更は以前の案・AI結果を無効にする。

## 契約・検証範囲

- `PresentationState.audioConnection` は任意項目。LAN IPv4・HTTP・ポート・トークンを検証し、受信停止時は削除する。MCPの分析材料やログに接続コードを含めない。旧手動試験入口も保持。
- `isPractice` は画面共有なしでの練習を示す。通常の発表開始の画面確認は維持し、練習もMac正本タイマーと同じ発表IDを使用する。
- 練習の時間入力は開いた時点の発表ID・設定revision・接続世代を固定する。確認中にいずれかが変わった場合や資料読込・発表開始/終了処理中は適用できない。閉じて現在の設定から開き直す。
- `Tests/IntegratedPracticeTests.swift` / `scripts/check_integrated_practice.py` は実MacModelの開始・終了、同発表の音声根拠、MCP依頼、リセットを合成peerで確認する。先に `bash scripts/check.sh mac` が必要。
- core/署名回帰、Mac/iPhoneビルド、MCP SDK往復、資料回帰を検証。NSHostingViewのホーム・終了後描画に加え、実Macアプリでホーム→練習、既存モデル取込み→受信開始→QR接続案内を確認した。実iPhoneの録音は未確認。
- 実iPhoneのマイク・Wi-Fi・権限、実ChatGPTの新ツール返却・助言品質、TestFlightのインストールは別途確認。連続送信・リアルタイム通知・正確な音声/スライド時計同期はまだ未実装で、今回取り込んだbranchにも完成実装はない。
