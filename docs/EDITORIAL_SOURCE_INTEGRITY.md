# 原稿要点選択の原文保持（Issue #68）

PR #58の `apps/SlidePacer` に対する合成データ回帰。#34/#56の実資料評価を置き換えず、MCP返却・本体統合・推論品質の成功とは区別する。

## 修正

- 原文ID抽出と条件補完で括弧対応の同じ文分割を使う。引用内の句点・改行で分断せず、元にない句点を付け足さない。本文の表と条件は行で区別しつつ、複数行の引用は保持する。
- 素のノートにある末尾の数字や `2:50` のような値を削除しない。ページ番号・発表メモ・試行回数・比率の区別は文字列だけでは証明できない。明確なPPTX placeholder等の構造情報による除外は今後の取込担当の範囲。曖昧な末尾値が候補として残ることを許容する。
- `Nつあります / N点です / N項目を挙げます` と `第一は… / 第二は…` 等の明示的・連続した番号付けを、同じ本文/ノート起源内で認識する。そのグループの一部が選ばれた場合だけ、グループ全体を同じcore/detailへ補完する。coreが一部を含む場合は全体をcoreに置き、短時間時にdetailだけ消えることを防ぐ。原文の項目不足・連番不一致は拒否し、存在しない項目を生成しない。選ばれていないグループや無関係な説明を常に追加しない。
- 確認・検証・実証・保証していない等の否定条件を、原文の文単位で保持する。否定の言い換えや事実判定はしない。

列挙認識はアラビア数字2〜32または漢数字二〜十、上記の明示構文と同一originの連続したSourcePointが対象。暗黙の列挙、自由な言い換え、全言語の否定、意味的な重複・判断根拠の完全性は保証しない。原文IDが有効でも編集品質が保証されるわけではない。

## 合成再現と検証

`make slidepacer-test`：既存38ケースと新規7ケース。旧テスト2箇所の「裸数字/時刻を捨てる」という期待は、今回修正する不具合そのものなので更新した。空白ページの拒否は維持する。

追加ケース：引用内の未検証文/入れ子括弧、本文複数行引用、末尾数字・時刻・負数・割合、部分列挙の完成と短時間時保持、未選択グループの非採用、欠落/誤順序の拒否、本文/ノートの否定と無関係文の除外。

`make slidepacer-build`で署名なしMacビルドも確認する。実資料・モデル・外部APIをテストへ使わず、実ChatGPT/実機/配布は未検証のまま。

## 未解決の説明量と時間配分

合成608文字のcore/detailを35秒で「詳しく」とする現行挙動は再現済み。今回 `EditorialPlanner` の秒数や重要度を変更しない。発話速度の前提・利用者による確認・説明量超過警告等を別途設計し、文章量に対して実行可能な配分かを評価する必要がある。原文の数値を守るために全文を自動的に話すことを推奨する仕様ではない。
