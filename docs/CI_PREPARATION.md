## 資料の趣旨に沿うと考える確認

- 準備資料・ワークフローの構文と、手動の準備資料チェック。
- GitHub Actionsの起動・終了・ログが確認できること。
- 認証情報を表示せず、Apple APIでアプリ・TestFlightグループを読み取る接続確認。
- 設計として、署名・配布・通知の段階と必要設定を整理すること。

基本ワークフローの作成は明記されているが、上記の個別接続テスト全てが明示的に許可されているわけではない。主催者の追加指示があれば優先し、境界が曖昧な実験は確認する。

## 本番開始の指示を受けるまで行わないこと

最終アプリや動作するモックの実装、アプリのビルド・署名・アップロード、TestFlight審査提出・配布。ダミーアプリを用いた配布テストも事前には行わない。

現在のPreparation documentsは資料の存在を確認する手動ワークフローであり、iPhone/MacアプリをテストするCIや実動するCDではない。この成功から署名・配布成功は判断できない。
