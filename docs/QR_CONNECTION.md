# 近くのMacとQR接続

## 利用方法

通常はiPhoneの接続画面で検索を開始し、見つかったMacを選びます。アプリが前面へ戻ったときも、停止前に検索していれば再開します。通信版が違うMacは、黙って隠さず両アプリの更新を案内します。

検索で出ない場合:
1. Macで「QRでつなぐ」を開く（待機未開始なら開始）。
2. iPhoneで「QRでつなぐ」を開き、カメラを許可してMacのQRを読み取る。
3. Mac側で、そのiPhoneからの接続を許可する。

QRは10分有効。期限切れ・ネットワーク変更時は「QRを更新」。Wi-Fiと有線LANが両方ある場合は、QR画面の接続先からiPhoneと同じネットワークを選べます。カメラを使えない端末は近隣検索を使用します。

両端末のローカルネットワーク権限が必要です。QR経路は同一LANのIPv4（プライベート/リンクローカル）へ直接TCP接続するため、Bonjourの探索が遮断されても端末間TCP通信が許可されていれば使用できます。端末間通信そのものが遮断される会場Wi-Fiでは、両端末を同じテザリング/許可されたネットワークへ接続してください。QRはインターネット中継やネットワーク制限回避ではありません。

## 実装

通常経路はMCSession暗号化を維持。QR経路はNetwork.frameworkのTLS 1.2 PSK / AES-128-GCM、256bit乱数鍵をメモリ上に生成。鍵を含むQRは保存・ログ出力しない。QRを配信画面やチーム共有スクリーンショットに含めない。停止/QR更新で鍵を破棄、10分で新規受付終了。接続済みセッションは期限後も継続できる。

TLS認証だけで資料を送らず、Macの明示承認後にWireCodecメッセージ/画像を解放する。近隣接続とQR接続を同時に承認しない。旧接続の非同期callbackをNWConnectionのidentityで拒否、受信は512KiB/packet、送信待ちは1MiBに制限。既存の画像identity検証と1枚ずつのACKを維持。

## 検証の区別

- `bash scripts/check.sh core`: 不正QR、期限、IPv4宛先、鍵長、版の検証。
- Mac/iPhoneのネイティブビルドを両方実施する。
- 明示的なローカルネットワーク統合検証: `Tests/DirectPairingIntegration.swift` を `Shared/DirectPairing.swift` とswiftcでコンパイル。通常実行で画像相当180KiBと複数packetの順序を検証。`--wrong-key` でTLS認証失敗を検証。
- 実iPhoneカメラでのQR読み取り、会場LANでのMac複数台探索、画面操作の実機受入は別途必要。ローカル同一Mac内の通信成功を実機成功と表現しない。
