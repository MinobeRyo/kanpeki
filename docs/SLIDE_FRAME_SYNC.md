# スライド画像とページ観測の同期（#20）

## 何を対応付けるか

`PresentationState.frameIdentity`とJPEGのヘッダーに、共有/接続ごとの`sessionID`、更新世代`revision`、観測した`slideID`/`slideIndex`を付ける。資料パスは端末間に送らない。ページ変更、共有切替、再接続では古いidentityを再利用しない。`frameReady=false`では両画面を「スライド画像を更新中」にし、旧画像を消す。iPhoneは一致するidentityの画像だけを採用し、更新待ち/未同期/3秒以上画像更新なしでは操作しない。鮮度判定には単調時計を使う。

## 旧バッファを新ページとしない取得

同期用画像はScreenCaptureKitの既存stream/idleキャッシュから取らず、`SCScreenshotManager`へ新規取得を要求する。PowerPoint同期中はページ観測→新規取得→再観測の順に行い、前後の資料パス・ID・index・枚数が一致し、取得開始時のidentityが現在も有効で、処理が2秒未満の場合だけ送る。取得は同時に1つのみ、通常は800msのページ観測に追従。同期停止中の画面プレビューは1秒ごとの新規取得で、ページidentityはnilのまま区別する。停止や対象変更後に完了した取得は捨てる。

既存streamは共有ライフサイクル/停止検出に保持するが、このモードではバッファをJPEG化・表示・送信しない。JPEGは最大180KiB、品質を落としても収まらなければ更新待ちとする。アスペクト比とaspect-fit表示は維持し、トリミングや独自スライド再描画は行わない。

新共有/停止時には取得requestIDを無効化してTaskをcancelし、古い取得が返らなくても新共有の要求枠を作れる。古いTaskの完了処理は同じrequestIDの枠だけを解放する。stream停止callbackは現在のstreamと同一の場合だけ処理し、start/stopのawait完了も世代が変わっていれば新状態を上書きしない。OSの画面取得自体のキャンセル完了時刻は保証しない。

## 転送・操作

- JPEG packet v2: `KF,2`、2-byteヘッダー長、最大1KiBのJSON（sequence/identity）、最大180KiBのJPEG。
- 既存の暗号化MultipeerConnectivityと明示的接続承認を維持。未ACKフレームは1枚まで。受信側は状態不一致で表示しないフレームもACKし、古い1枚で転送を詰まらせない。独自の再送/画像キューは追加しない。
- delegateからmainへ渡すstate/frame/ACKは接続世代を確認し、切断・再接続以前にキューへ入ったcallbackを新接続で適用しない。
- 戻る/進むには表示中`frameIdentity`を添え、Macは現在のidentityと一致する場合だけ受ける。実行前のPowerPoint位置も読み、表示画像のページと異なる場合は操作せず再同期する。
- discovery/contextをv2へ更新して、identityを理解しない旧Mac/iPhoneとの混在接続を受け付けない。**両アプリを同じ対応版へ更新する必要がある**。JSONの任意フィールド互換だけで旧画像を安全と扱わない。QR/WebSocket移行ではない。

## 限界・残件

これは**取得前後のページ観測**の一致であり、PowerPointが実際に描画したピクセルのページIDを画像解析で証明するものではない。観測間隔内の素早い往復、アニメーション/遷移の途中、発表用以外のウィンドウを選択した場合の見た目まで保証しない。800msポーリングでMac側の手動変更を知るまでの遅れも残る。前後観測一致を実描画精度や厳密な遷移時刻の測定と呼ばない。

自動テスト：別session、別page、遅延/順序逆転、取得中、共有停止、期限切れlease、ヘッダー/サイズ/旧形式の拒否と操作identity。必要ビルドはMac/iPhone双方。

未実施：実機のPowerPoint手動/リモート連打、縦長・横長資料の実表示、アニメーション、接続切替/画像遅延/パケット損失、外部ディスプレイ、スクリーンショット更新速度/負荷、画面収録許可、TestFlight確認。#20全体の実機受入完了とは扱わない。
