# チームでの進め方

担当は本人の依頼に基づき、AIが勝手に決めない。開始後は担当と目的をIssueで共有し、並行作業はbranch/worktreeを分ける。依存関係は関連Issueと必要な入出力で示す。

各自のCodexにはAGENTS.mdと対象仕様書を読ませる。開始・再開・意味のある進展・方針変更・ブロック・停止前・完了時に短く報告する。進捗の詳細はIssue、決定した仕様はPRで管理する。

マージ時は現在のGitHub保護ルールと最新mainを確認する。レビュー必須件数は所有者の合意で設定し、CIの結果と人間の動作確認を区別する。チェック未接続・無料枠枯渇時に保護を回避して成功扱いにしない。

SlackのAI相談はメンションとスレッドを入口にする案。連携・権限・対象チャンネルを確認してから有効化する。全会話の常時読み取りを既定にしない。AIの担当割り振りは提案とし、人間の依頼・受諾で確定する。

実際のworktreeコマンドとIssue報告の手順は[TEAM_WORKFLOW.md](TEAM_WORKFLOW.md)。古い担当表を現在の完了状態として扱わず、最新Issueを確認する。

作業を増やす際の短い手順は[WORKTREES.md](WORKTREES.md)。まず `python3 scripts/team.py list` でローカルの重複を確認する。

## AIの作業サイクル

最新Issueを読む → 今やることを追記 → 実装／調査／検証 → 結果と不足を追記 → 次の未対応作業を確認、を依頼目的が満たされるまで繰り返す。全AIにAGENTS.mdの「Issueを使った継続的な作業管理」を適用する。

報告の例：

```text
現在：スライドと原稿の対応を確認しています。
完了：読込テスト成功。未対応：切断後のページ復帰。
次：同Issueの復帰条件を検証。根拠：対象PR／テスト結果。
```

冒頭はSlack向けに3行・200文字程度とし、下に必要な検証根拠を書く。投稿頻度ではなく、他の人が現状と次の一手を判断できることを優先する。担当範囲内の不足は許可済みの作業として進めるが、別担当の仕事は関連Issueを通じて調整する。

再開時は未対応と次の行動から継続する。作業を終える前に残件を確認し、残件なし・別Issueで継続・人間の判断待ちのいずれかを明示する。無期限の常駐実行や自動起動をこの文書だけで有効にしたとは説明しない。
