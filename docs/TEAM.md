# チームでの進め方

担当は本人の依頼に基づき、AIが勝手に決めない。開始後は担当と目的をIssueで共有し、並行作業はbranch/worktreeを分ける。依存関係は関連Issueと必要な入出力で示す。

各自のCodexにはAGENTS.mdと対象仕様書を読ませる。開始・方針変更・ブロック・完了時だけ短く報告する。進捗の詳細はIssue、決定した仕様はPRで管理する。

マージ時は現在のGitHub保護ルールと最新mainを確認する。レビュー必須件数は所有者の合意で設定し、CIの結果と人間の動作確認を区別する。チェック未接続・無料枠枯渇時に保護を回避して成功扱いにしない。

SlackのAI相談はメンションとスレッドを入口にする案。連携・権限・対象チャンネルを確認してから有効化する。全会話の常時読み取りを既定にしない。AIの担当割り振りは提案とし、人間の依頼・受諾で確定する。

実際のworktreeコマンドとIssue報告の手順は[TEAM_WORKFLOW.md](TEAM_WORKFLOW.md)。古い担当表を現在の完了状態として扱わず、最新Issueを確認する。
